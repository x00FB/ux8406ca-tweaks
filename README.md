# ASUS Zenbook Duo UX8406CA on Fedora 44 KDE

Scripts and notes for running the **ASUS Zenbook Duo UX8406CA** (2025, Arrow Lake) on Linux with KDE Plasma.

This project fixes the following issues:

- [The lower screen stays on when the keyboard is docked](#lower-screen-stays-on-when-the-keyboard-is-docked)
- [Fn keys, Fn-lock and keyboard backlight don't work](#fn-keys-fn-lock-and-keyboard-backlight-dont-work)
- [Touch on the lower screen registers on the upper one](#touch-on-the-lower-screen-registers-on-the-upper-one)
- [OLED flicker](#oled-flicker-psr)
- [Slow boot and stalls after login](#slow-boot-and-stalls-after-login)
- [The clock is hours off until NTP sync](#the-clock-is-hours-off-until-ntp-sync)
- [VLC loses audio after pause or track change](#vlc-loses-audio-after-pause-or-track-change)
- [The battery charge limit resets after reboot](#the-battery-charge-limit-resets-after-reboot)
- [Discover checks for updates at every login](#discover-checks-for-updates-at-every-login)

Tested on:

- Fedora 44 KDE, kernel 7.2.8, KDE Plasma 6.7 (Wayland)
- Intel Core Ultra 9 285H (Arrow Lake), video driver `i915`
- Keyboard: `0b05:1bf2` (docked, USB), `0b05:1bf3` (Bluetooth)

> **Note:** this is for the **UX8406CA (Arrow Lake)**. The 2026 **UX8407AA (Panther Lake)** has different
> hardware (keyboard `0b05:1cd7`, different display and audio problems) and is not covered here.

## Lower screen stays on when the keyboard is docked

A user service watches USB events and turns `eDP-2` off while the keyboard is docked and back on when it's
undocked. On enable, it places `eDP-2` below `eDP-1` (at 0,1125, which matches scale 1.6; override with
`DUO_LOWER_POS`, or set it empty to keep the current position).

Brightness works around a KWin bug (https://bugs.kde.org/show_bug.cgi?id=494730): the `eDP-1` slider writes
its value to both hardware backlights, while the `eDP-2` slider only dims the image in software. The script
keeps `eDP-2` pinned at 100% and copies the upper panel's hardware backlight to it when enabling it. **Use the
upper slider or the brightness keys to control both panels.**

Install:

- `lower-screen/duo-screen` → `~/.local/bin/` (commands: `watch|toggle|on|off|status`)
- `lower-screen/duo-screen.service` → `~/.config/systemd/user/`, then `systemctl --user enable --now duo-screen`
- `lower-screen/duo-screen-toggle.desktop` → `~/.local/share/applications/`. This toggles the lower screen
  manually until the next dock/undock. Bind it to a hotkey, for example F18 (the lower-screen key, see below).

Log: `journalctl --user -u duo-screen`.

## Fn keys, Fn-lock and keyboard backlight don't work

This uses the HID-BPF program (keyboard-bpf only) from
[cceelen/asus-zenbook-duo-ux8406](https://github.com/cceelen/asus-zenbook-duo-ux8406) at commit
`5e5fdebca3106a03ef68dfa3e29fabca3fe3d400`, with two local changes in `src/*.bpf.c` (marked `local:`):

- Fn+F4 cycles the backlight 0→1→2→3→0
- the top row sends hotkeys by default (Fn+Esc switches it to F1–F12)

It works both docked and over Bluetooth.

Build (needs `clang` and `libbpf-devel`):

    cd keyboard-bpf
    clang -g -O2 -Wall -Werror --target=bpf -Iinclude -Wno-microsoft-anon-tag -fms-extensions \
      -D__TARGET_ARCH_x86 -c src/ASUS__Zenbook-Duo-UX8406-Keyboard.bpf.c \
      -o 0010-ASUS__Zenbook-Duo-UX8406-Keyboard.bpf.o

Install, then reconnect the keyboard:

    sudo udev-hid-bpf install --force 0010-ASUS__Zenbook-Duo-UX8406-Keyboard.bpf.o && sudo udevadm control --reload

This puts the `.bpf.o` into `/etc/udev-hid-bpf/` and a `99-hid-bpf-*.rules` file into `/etc/udev/rules.d/`.
A copy of the generated rule is in `keyboard-bpf/` for reference.

Key mapping after installation: F5/F6 brightness, F9 mic mute, F8 → F19, F11 → PROG1, F12 → F13,
lower-screen key → F18. You can assign the remapped keys in KDE's shortcut settings.

## Touch on the lower screen registers on the upper one

In System Settings → Touchscreen, map the devices to outputs:

- `ELAN9008:00 04F3:4447` → `eDP-1` (upper)
- `ELAN9009:00 04F3:4448` → `eDP-2` (lower)

The devices may show up in the dropdown with empty names. In that case, map the first one to the first
screen and the second one to the second screen.

Plasma stores the mapping in `~/.config/kcminputrc`. To set it there instead, add:

    [Libinput][1267][17479][ELAN9008:00 04F3:4447]
    OutputUuid=<eDP-1 uuid>

    [Libinput][1267][17480][ELAN9009:00 04F3:4448]
    OutputUuid=<eDP-2 uuid>

The output UUIDs are generated by KWin and differ between installations. Look them up in
`~/.config/kwinoutputconfig.json` (the `uuid` next to `"connectorName": "eDP-1"` / `"eDP-2"`), then log out
and back in.

## OLED flicker (PSR)

Panel Self Refresh makes dark-grey areas flicker or dim. Disable it:

    sudo grubby --update-kernel=ALL --args="i915.enable_psr=0"

## Slow boot and stalls after login

The NVMe drive behind Intel VMD loses interrupts (`nvme ... timeout, completion polled` in the log), which
causes 30-second I/O hangs. Disable VMD in the BIOS:

Advanced → VMD setup menu → VMD controller: Disabled

> Do this only if you don't need Windows on the same drive, or switch Windows to the standard NVMe driver
> first. Otherwise Windows won't boot.

## The clock is hours off until NTP sync

The hardware clock is in local time (left over from Windows). Switch it to UTC:

    sudo timedatectl set-local-rtc 0 && sudo hwclock --systohc --utc

## VLC loses audio after pause or track change

The `vlc-plugin-pipewire` output module is buggy. Without it, VLC works through pipewire-pulse:

    sudo dnf remove vlc-plugin-pipewire

## The battery charge limit resets after reboot

ASUS firmware resets `charge_control_end_threshold` to 100 on boot, and KDE doesn't restore it.
`battery/battery-charge-limit.service` saves the current threshold to `/var/lib/battery-charge-limit/end`
on shutdown and restores it on boot (80 by default). **Set the limit in KDE settings as usual and it now
survives reboots.**

    sudo install -m644 battery/battery-charge-limit.service /etc/systemd/system/
    sudo systemctl daemon-reload && sudo systemctl enable --now battery-charge-limit

## Discover checks for updates at every login

The Discover notifier runs a PackageKit update check at login, which slows the session start.
Copy `autostart/org.kde.discover.notifier.desktop` (`Hidden=true`) to `~/.config/autostart/` to disable it.
Delete the file to undo.
